# clinker-app

Одно приложение — одна ответственность. Экран не вызывает модель. Модель не читает журнал.
Файл `*.analysis.md` — бриф, всегда в `docs`. Если он расходится с кодом, верен код.
Открывай бриф, только если задача назвала файл.
В новом брифе есть пример структуры: модули, кто кого вызывает, ответственность каждого модуля.

Куда класть правку:

- кнопка и вёрстка — `apps/assistant_web`
- ход, журнал и связь с агентом — `apps/assistant`
- протокол модели — `apps/assistant_inference`
- карточки — `apps/cards`

Это текущие ответственности, не закрытый список. Чужая работа в существующее приложение не кладётся. Новая ответственность — новое приложение `apps/<имя>`: свой `mix.exs`, своя дверь, свой процесс. Экран этой фичи остаётся в `assistant_web` и вызывает дверь нового приложения. `assistant` второй работой не растёт.

Чужое приложение зовёт фасад. Экран и ход зовут `Assistant`. Карточки снаружи зовут `Cards`. Модули за фасадом снаружи не вызываются.

Один модуль — одна ответственность. Вторая ответственность — новый модуль.

Файл длиннее 150 строк читай от найденной строки, не целиком.
Новый модуль — со второго реального вызова.
Новый тест — только на фразу из задачи.
Патч в другом приложении — остановись и покажи список файлов.

## Кто вызывает модуль

Перед правкой публичной функции остановись и из корня зонтика выполни:

```
mix xref graph --sink lib/путь/к/файлу.ex
```

Пример для `Assistant.Journal`:

```
mix xref graph --sink lib/assistant/journal.ex
```

`mix xref callers` здесь не использовать: в корне зонтика эта команда не запускается, а из каталога приложения не видит зависимости.

Путь в команде и в ответе без префикса `apps/<приложение>/`. `lib/assistant/journal.ex` в выводе — это `apps/assistant/lib/assistant/journal.ex`.

Дальше смотри только границу приложений. Вызовы внутри того же приложения — правь. В списке есть файл другого приложения — остановись и покажи файлы, само приложение не меняй. Полный `mix xref graph` без `--sink` не запускай.
